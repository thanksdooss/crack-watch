# 색 보정 — 조명이 달라도 같은 색으로 읽히는가

`python -m ml.eval.color_calibration`으로 다시 만든다. 난수 시드 고정.

> **합성 실험이다.** 실제 스마트폰으로 찍은 사진이 아니라, 조명에 따른 색 이동을
> 표준 색순응 모델로 흉내 낸 값이다. 알고리즘이 원리대로 도는지를 보는 것이고,
> 실촬영 측정치는 아래 '아직 비어 있는 칸'에 따로 채운다.

## 읽는 법

ΔE00은 사람이 느끼는 색 차이를 재는 표준 단위다. 대략 **1이면 훈련된 눈이 겨우
구분**, 2~3이면 나란히 놓으면 다르다는 걸 알아보는 정도, 10을 넘으면 누가 봐도 다른 색이다.

보정 계수는 **무채색(흰·회색·검정) 스와치에서만** 구한다. 빨강·파랑은 계산에 넣지 않고
검증에만 쓴다. 전부 넣고 맞추면 잘 맞는 게 당연해서 숫자가 아무것도 증명하지 못한다.

## 1. 색 오차 (ΔE00 평균)

| 조명 | 무채색 보정 전 | 무채색 보정 후 | **검증색(빨강·파랑) 보정 전** | **보정 후** | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| 맑은 날 바깥 (주광) | 0.52 | 0.54 | **0.23** | **0.31** | good |
| 흐린 날 바깥 | 1.68 | 0.50 | **1.56** | **0.25** | good |
| 건물 안 형광등 | 5.00 | 0.21 | **3.58** | **0.72** | good |
| 백열등 아래 | 10.48 | 0.56 | **6.55** | **1.66** | good |
| 해질 무렵 | 13.34 | 0.55 | **9.66** | **2.55** | good |
| 해질 무렵 + 역광 | 13.07 | 0.65 | **14.04** | **2.61** | good |

가장 나쁜 조건은 «해질 무렵 + 역광»으로, 보정 전 검증색 오차가 14.0이다 — 누가 봐도 다른 색으로 찍혔다는 뜻이다. 보정 후 2.6까지 내려간다.

## 2. '붉게 변했는가' 판정

캠페인이 실제로 묻는 질문이다. 표지의 여러 중간 상태를 각 조명에서 찍었다고 보고,
보정 전후로 파랑/빨강 판정이 맞는지 센다. **거짓 빨강**은 파란 상태를 붉다고 잘못 읽은
횟수 — 그대로 오경보가 된다.

| 조명 | 보정 전 정확도 | 보정 후 정확도 | 보정 전 거짓 빨강 | 보정 후 거짓 빨강 |
| --- | ---: | ---: | ---: | ---: |
| 맑은 날 바깥 (주광) | 100% | 100% | 0 / 4 | 0 / 4 |
| 흐린 날 바깥 | 100% | 100% | 0 / 4 | 0 / 4 |
| 건물 안 형광등 | 100% | 100% | 0 / 4 | 0 / 4 |
| 백열등 아래 | 88% | 100% | 1 / 4 | 0 / 4 |
| 해질 무렵 | 75% | 100% | 2 / 4 | 0 / 4 |
| 해질 무렵 + 역광 | 75% | 100% | 2 / 4 | 0 / 4 |

전체 합계: 거짓 빨강 **5/24 → 0/24**.

판정에 쓴 필름의 파랑·빨강 색값은 **가정한 값**이다. 실제 필름을 측정한 것이 아니다.
우리가 만드는 것은 필름이 아니라 사진 속 색을 믿을 수 있게 만드는 절차이고,
이 실험은 그 절차가 조명 변화에 견디는지만 본다.

## 한계

- 합성 모델은 조명 변화를 von Kries 색순응으로 근사한다. 실제 카메라의 색 처리
  (톤 커브, 채도 강화, HDR 합성)는 더 복잡하고 기종마다 다르다.
- 스와치를 사진에서 찾아내는 검출 오차는 이 표에 들어 있지 않다. 검출은 다음 단계다.
- 인쇄 색 편차, 카드가 접히거나 젖는 경우, 그림자가 카드 일부에만 지는 경우는 미반영.
